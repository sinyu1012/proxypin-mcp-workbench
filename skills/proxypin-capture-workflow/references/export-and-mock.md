# 数据导出与 Mock 管理

## 完整导出个人数据

优先使用应用官方导出能力。仅当官方导出不完整、目标是用户自己的账号且用户明确要求时，才使用抓包得到的私有接口。

1. 找到原始记录接口，而不只是图表或统计接口。
2. 从响应中的最早时间字段推导边界，并用相邻日期或分页验证。
3. 判断分页方式：日期、游标、偏移量、页码、`loadMore` 或时间范围；不能假定当前屏幕就是全部数据。
4. 以受控频率顺序重放。授权信息只放在进程环境或权限受限的临时文件，不能写入源码。
5. JSON 保留完整记录字段，但移除带凭据的 URL 和非必要跟踪字段。
6. 同时生成适合查看的 UTF-8 BOM CSV 和保真 JSON。
7. 优先按稳定记录 ID 去重；没有 ID 时才使用有文档说明的组合键。
8. 验证 JSON 数量、解析后的 CSV 行数、唯一 ID、最早/最晚时间和日期覆盖范围。
9. 如果存在独立统计接口，用重合日期范围进行交叉核对。
10. 输出简短说明，记录范围、数量、校验、脱敏内容和隐私提示。

不要用 `wc -l` 统计 CSV 记录；带引号字段可能包含换行，必须使用 CSV 解析器。

## Mock 合集

定制版 ProxyPin 的 Mock 合集由请求重写规则的 `group` 字段和管理器级 `groups` 映射实现。

- 首页工具栏的 `Mock` 按钮打开规则管理器。
- 没有 `group` 的旧规则归入“未分组”，并保持原有启用状态。
- 合集开关可以整体控制其中所有规则，但不会破坏规则自己的开关。
- 删除合集时把规则移入“未分组”，不能删除规则正文。
- 支持单条或多选移动规则。
- MCP `add_rewrite_rule` 接受可选 `group`；`list_rewrite_rules` 返回合集与规则归属。

修改 Mock 前，确认用户明确要求写操作，并且目标是自己的应用或授权测试环境。优先使用精确 URL 与方法匹配。全局重写、合集和单条规则是三层独立状态，不能压缩成一个布尔值。

代码修改至少验证：

1. 匹配逻辑跳过已禁用合集。
2. JSON 迁移保持旧配置可用。
3. 多窗口操作会持久化新增、启用、重命名和删除合集。
4. MCP 查询与新增工具公开合集元数据。
5. 定向 `flutter analyze` 没有错误。
6. 目标平台构建成功。
7. 运行界面显示 Mock 入口，合集页可以渲染，重启后规则仍能恢复。
